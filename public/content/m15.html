Security

  • XSS is the main threat. Angular auto-sanitizes values by context (HTML, style, URL, resource-URL) — interpolation is always escaped, so {{ userInput }} is safe by default.
  • [innerHTML] binds sanitized HTML (strips scripts). To render trusted raw HTML, use DomSanitizer.bypassSecurityTrustHtml(...) — but only on content you fully trust (this is the risky escape hatch behind pipes like nlToBr/safe).
  • Avoid ElementRef.nativeElement.innerHTML = ... and template concatenation of user data. Use Angular's bindings.
  • CSP (Content Security Policy) + Trusted Types add defense-in-depth. Angular integrates with Trusted Types. Also: HttpOnly cookies / CSRF tokens (Angular's HttpClient has XSRF support), and never put secrets in the client bundle.
Interview trap

"How does Angular prevent XSS?" Contextual auto-sanitization + always-escaped interpolation. You only become vulnerable when you deliberately bypass it (bypassSecurityTrust*) or manipulate the DOM directly.

Accessibility (a11y)

  • Target WCAG AA: sufficient color contrast, visible focus states, full keyboard operability.
  • Use semantic HTML first (<button>, <nav>, <label>); add ARIA only to fill gaps (aria-label, role, aria-live for dynamic announcements).
  • Focus management: move focus into dialogs, trap it, restore on close. The Angular CDK a11y module provides FocusTrap, LiveAnnouncer, and FocusMonitor.
  • Tools: axe for automated checks; test with a keyboard and a screen reader.
