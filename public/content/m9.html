For shared state across a large app, NgRx keeps one centralized, read-only store with a strict one-way flow. You never mutate state directly — you dispatch actions; reducers produce new state; effects handle async; selectors read.

Component ──dispatch(action)──► Reducer ──► Store (new state) ──select──► Component │ ▲ └──► Effect ──(API call)──► dispatch(success/failure)

Actions — "something happened" (the async triad)

export const search        = createAction('[Q] Search', props<{ payload: Req }>());
export const searchSuccess = createAction('[Q] Search Success', props<{ data: Q[] }>());
export const searchFailure = createAction('[Q] Search Failure', props<{ error: any }>());

Reducer — pure (state, action) => newState, never mutates

export const reducer = createReducer(initialState,
  on(search,        (s) => ({ ...s, isLoading: true })),
  on(searchSuccess, (s, { data }) => ({ ...s, isLoading: false, data })),
  on(searchFailure, (s, { error }) => ({ ...s, isLoading: false, error })),
);

Effect — side effects live here

getQuestions$ = createEffect(() => this.actions$.pipe(
  ofType(search),
  switchMap(({ payload }) => this.api.search(payload).pipe(
    map(res => searchSuccess({ data: res.items })),
    catchError(err => of(searchFailure({ error: err }))),  // map error to a failure action
  )),
));

Selector — memoized reads

export const selectState = createFeatureSelector<QState>('questions');
export const selectList  = createSelector(selectState, s => s.data);
Interview

"Why can't a reducer call an API?" Reducers must be pure — same inputs, same output, no side effects — so state changes are predictable, testable, and time-travel-debuggable. Async/side effects go in effects. Also know: immutability (why ...spread) is what lets OnPush and memoized selectors detect change by reference.
