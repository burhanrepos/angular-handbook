Change Detection & OnPush

Change detection keeps the screen synced to data. OnPush tells Angular to re-check a component only when: an input reference changes, an event fires in it, an async pipe emits, or a signal it reads changes — letting it skip whole subtrees.

Why the conventions exist

OnPush reacts to reference changes, not mutations. That's exactly why NgRx uses immutable updates, why signals use .set(), and why the async pipe is preferred — they all produce the notifications OnPush needs.

GraphQL & Apollo

Alongside REST, Angular apps use Apollo for GraphQL. A code-generation workflow (npm run generate) turns .graphql files into typed service classes. Queries use .watch().valueChanges (an Observable); mutations use .mutate(). Access is wrapped in a facade so components never touch Apollo directly.

Testing (Vitest / Jasmine)

describe('CountItemComponent', () => {
  let fixture: ComponentFixture<CountItemComponent>;
  beforeEach(async () => {
    await TestBed.configureTestingModule({ imports: [CountItemComponent] }).compileComponents();
    fixture = TestBed.createComponent(CountItemComponent);
    fixture.detectChanges();
  });
  it('should create', () => expect(fixture.componentInstance).toBeTruthy());
});

TestBed builds an isolated component; fixture wraps it (.componentInstance, .nativeElement, .detectChanges()); expect asserts. DI lets you provide mocks. Test types: unit, component (with DOM), integration, and E2E (Cypress/Playwright).
