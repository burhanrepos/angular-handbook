The golden rule of Angular data flow: data flows DOWN via inputs, events flow UP via outputs. A child never reaches into its parent; the parent hands data down, the child emits events up.

Inputs & Outputs modern

readonly item = input.required<Item>();          // required input (parent MUST pass)
readonly size = input<number>(80);               // optional, with default
readonly replySubmitted = output<ReplyPayload>(); // event out

// reading an input is a FUNCTION CALL — the #1 beginner mistake is forgetting ()
const current = this.item();
this.replySubmitted.emit({ questionId, replyText });

Signals: reactive state

A signal is a box holding a value; when you change it, Angular re-renders whatever reads it.

count = signal(0);
this.count();              // READ  (call it)
this.count.set(5);         // WRITE (replace)
this.count.update(n => n+1);// WRITE (from previous)

color = computed(() => this.score() >= 80 ? 'green' : 'red'); // derived, cached, auto-updates

constructor() {
  effect(() => { if (this.description()) this.checkOverflow(); }); // side effect on change
}
  • computed() — derived value; recalculates only when its signal dependencies change. Prefer this over calling methods in templates.
  • effect() — run a side effect when signals change. Use sparingly.
  • Never use .mutate() — always .set() / .update().
Interview

"Why computed() instead of a getter?" A computed is memoized — it recomputes only when a dependency changes. A getter/method in a template runs on every change-detection cycle.
