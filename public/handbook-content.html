Module 01Foundations

Fundamentals: components, templates, binding

Angular is a framework for building web apps. Instead of manually updating the DOM, you declare what the UI should look like and Angular keeps the screen in sync with your data. The core unit is the component — a reusable, self-contained piece of UI. A page is a tree of components nested like custom HTML tags.

Anatomy of a component

A component is a TypeScript class with a @Component decorator, usually split across three files: the .ts (logic/data), .html (template), and .scss (scoped styles).

@Component({
  selector: 'app-star-rating-display',   // the custom tag: <app-star-rating-display />
  imports: [DecimalPipe, MatIconModule], // standalone: declares its own deps
  templateUrl: './star-rating-display.component.html',
  styleUrl: './star-rating-display.component.scss',
  changeDetection: ChangeDetectionStrategy.OnPush,
})
export class StarRatingDisplayComponent {
  rating = input<number>(0);   // data in, from a parent
  stars = computed(() => { /* which stars to fill */ });
}
  • selector — the tag used to place this component elsewhere. The app- prefix avoids clashing with real HTML.
  • Scoped styles — styleUrl CSS affects only this component, never leaking out. A major Angular feature.
  • Standalone — modern components declare dependencies in imports. You do not write standalone: true; it's the default.

The four things every template does

TechniqueSyntaxDirection
Interpolation{{ rating() }}class → screen (text)
Property binding[class.full]="x"class → element property
Event binding(click)="save()"element event → class
Control flow@if / @forshow / repeat elements
Mental model

Angular is a tree of components. Each keeps its slice of the screen in sync with its data. You declare the relationship (bindings) once; Angular does the updating forever.

Module 02Foundations

Component I/O & Signals

The golden rule of Angular data flow: data flows DOWN via inputs, events flow UP via outputs. A child never reaches into its parent; the parent hands data down, the child emits events up.

Inputs & Outputs modern

readonly item = input.required<Item>();          // required input (parent MUST pass)
readonly size = input<number>(80);               // optional, with default
readonly replySubmitted = output<ReplyPayload>(); // event out

// reading an input is a FUNCTION CALL — the #1 beginner mistake is forgetting ()
const current = this.item();
this.replySubmitted.emit({ questionId, replyText });

The parent wires them with brackets:

<app-qa-card [item]="question" (replySubmitted)="handleReply($event)" />
BracketsDirectionPurpose
[ ]in (down)property / input binding
( )out (up)event / output binding
[( )]bothtwo-way ("banana in a box")

Signals: reactive state

A signal is a box holding a value; when you change it, Angular re-renders whatever reads it.

count = signal(0);
this.count();              // READ  (call it)
this.count.set(5);         // WRITE (replace)
this.count.update(n => n+1);// WRITE (from previous)

color = computed(() => this.score() >= 80 ? 'green' : 'red'); // derived, cached, auto-updates

constructor() {
  effect(() => { if (this.description()) this.checkOverflow(); }); // side effect on change
}
  • computed() — derived value; recalculates only when its signal dependencies change. Prefer this over calling methods in templates.
  • effect() — run a side effect when signals change. Use sparingly.
  • Never use .mutate() — always .set() / .update().
Interview

"Why computed() instead of a getter?" A computed is memoized — it recomputes only when a dependency changes. A getter/method in a template runs on every change-detection cycle.

Directives & Control Flow

Built-in control flow modern

@if (isFormArray) { <chip-grid/> } @else { <input/> }

@for (option of options; track option.id) {
  <mat-option [value]="option">{{ option.name }}</mat-option>
} @empty {
  <p>Nothing found</p>
}

@switch (state) {
  @case ('PENDING')  { <span>Pending</span> }
  @case ('ACCEPTED') { <span>Accepted</span> }
  @default           { <span>{{ state }}</span> }
}

@let total = price() * qty();   // name a value once, reuse in template
  • track is mandatory in @for — it identifies each item so Angular reuses DOM nodes instead of re-rendering the whole list. Use a stable id, or track $index.
  • Implicit vars in @for: $index, $first, $last, $even, $odd, $count.
Legacy

Older code uses *ngIf, *ngFor, *ngSwitch (structural directives with *). The @-blocks are faster and are the default now. Recognize both; write the new ones.

Directives: three kinds

  selector: '[clickOutside]',                       // attribute selector, in [brackets]
  host: { '(document:click)': 'onClick($event.target)' }, // host object, NOT @HostListener
})
export class ClickOutsideDirective {
  private el = inject(ElementRef);
  clickOutside = output<void>();
  onClick(t: EventTarget | null) { /* emit if outside */ }
}
Convention

Modern Angular: use inject() not constructor injection, output() not @Output, and the host object not @HostListener/@HostBinding.

Module 04Foundations

Services & Dependency Injection

Components manage the screen; the real logic (API calls, calculations, shared data) belongs in services. Components reach services via Dependency Injection.

@Injectable({ providedIn: 'root' })   // singleton for the whole app
export class PopularSearchTermsService {
  private http = inject(HttpClient);   // ask for deps — don't `new` them
  private env = inject(EnvService);

  getScheduledTerms(): Observable<Term[]> {
    return this.http.get<Term[]>(`${this.env.apiUrl}/scheduled`); // returns, doesn't subscribe
  }
}
  • providedIn: 'root' — one shared instance app-wide (a singleton). Two components injecting it get the same object.
  • DI benefits — sharing, testability (swap in mocks), no manual wiring.
  • Services return Observables; they don't subscribe, navigate, or open dialogs. The caller (component/effect) decides what to do.
Facade pattern

Services named *-facade.service.ts hide complexity (NgRx, GraphQL) behind simple methods and streams, so components stay ignorant of the machinery.

Interview

"inject() vs constructor injection?" Same DI system. inject() is a function callable in an injection context (field initializers, constructors, factories); it's cleaner, composes into helper functions, and avoids long constructor signatures. It's the modern default.

Module 05Foundations

HTTP & RxJS Observables

An Observable is a lazy stream of values over time. Angular uses them for HTTP, form changes, router events, and NgRx. Three habits: they're lazy (nothing runs until subscribed), you transform in .pipe(), and you must clean up.

this.searchControl.valueChanges         // stream of keystrokes
  .pipe(
    tap(() => this.loading.set(true)),    // side effect (no value change)
    debounceTime(300),                    // wait for a typing pause
    switchMap(term => this.api.search(term)), // cancels previous request
    takeUntilDestroyed(this.destroyRef),  // cleanup on destroy
  )
  .subscribe(results => this.results.set(results));

The map family (higher-order operators)

OperatorBehaviourUse for
switchMapcancel previous, keep latestsearch / typeahead
concatMapqueue in orderordered saves
mergeMaprun all in parallelindependent calls
exhaustMapignore new while busydouble-submit, polling

Consuming: prefer the async pipe

@if (data$ | async; as data) { {{ data.name }} }  // auto-subscribe + auto-unsubscribe
Cleanup rule

If you can use the async pipe, do. If you must .subscribe() in code, you must add cleanup — takeUntilDestroyed(destroyRef) (modern) or untilDestroyed(this) (legacy lib).

Interview

"Observable vs Promise?" A Promise resolves once and is eager. An Observable is lazy, can emit many values, is cancellable, and composes with operators. HTTP in Angular returns an Observable that fires only on subscribe.

Module 06Building blocks

Reactive Forms

Angular has template-driven and reactive forms; prefer reactive. You build the form as objects in TypeScript (the source of truth) and bind them to inputs.

form = new FormGroup({
  title:      new FormControl('', [Validators.required]),
  priority:   new FormControl(null),
  multivalued: new FormArray([]),          // dynamic list of controls
});
ClassRepresents
FormControlone field + its validity
FormGroupa set of named controls
FormArraya dynamic list of controls
<form [formGroup]="form">
  <input formControlName="title" />
  @if (form.get('title')?.hasError('required')) { <mat-error>Required</mat-error> }
</form>
<button [disabled]="form.invalid">Save</button>
  • Forms are streams: form.valueChanges / control.valueChanges are Observables — pipe them (Module 5).
  • patchValue updates some fields (safe, partial); setValue requires all.
  • States: valid/invalid, touched, dirty, pristine.
Interview

"Reactive vs template-driven?" Reactive: model defined in TS, synchronous, easy to test, scales, great for dynamic/complex forms. Template-driven: model built from directives in the HTML (ngModel), simpler for small forms, async. Also know custom validators (a fn returning ValidationErrors | null) and ControlValueAccessor (makes a custom component behave as a form control).

Module 07Building blocks

Routing

Routing maps URLs to components, swapping content without a full reload. Routes are checked top-to-bottom; first match wins.

const routes: Routes = [
  { path: 'login', component: LoginComponent },
  { path: 'products/:id', component: ProductComponent },        // :id = route param
  { path: 'admin',
    loadChildren: () => import('./admin.routes').then(m => m.routes), // lazy load
    canActivate: [authGuard] },
  { path: '**', redirectTo: '', pathMatch: 'full' },            // wildcard, MUST be last
];

Matched components render into <router-outlet>. Nested routes (children) fill nested outlets — that's how a persistent shell + swapping content works.

FeaturePurpose
loadChildrenlazy-load a feature only when visited (smaller initial bundle)
GuardscanActivate, canActivateChild, canMatch/canLoad, canDeactivate
Resolverspre-fetch data before the route activates
datastatic config per route (title, roles, feature flag)
// Functional guard (modern) — returns boolean or a UrlTree redirect
export const authGuard: CanActivateFn = () => {
  const auth = inject(AuthService); const router = inject(Router);
  return auth.isLoggedIn() ? true : router.createUrlTree(['/login']);
};

// Navigate / read params
inject(Router).navigate(['/products', id]);
const id = inject(ActivatedRoute).snapshot.paramMap.get('id');

In templates use routerLink, not href (which reloads): <a routerLink="/products">, and routerLinkActive="active" for the active class.

Module 08Building blocks

Pipes

A pipe transforms a value for display without changing the underlying data: {{ value | pipeName:arg }}.

@Pipe({ name: 'fileSize' })          // standalone by default
export class FileSizePipe implements PipeTransform {
  transform(value: number): string {
    const kb = value / 1024;
    return kb > 1024 ? `${(kb/1024).toFixed(1)} MB` : `${Math.round(kb)} KB`;
  }
}

Built-ins you'll use: date, number, currency, uppercase, json, slice, async. Chain with |, pass args with :.

Pure vs impure

A pure pipe (default) recomputes only when its input reference changes — cached and fast. An impure pipe (pure: false) runs every change-detection cycle (the async pipe is impure). Prefer pure pipes; this is why the codebase forbids method calls in templates.

Module 09Building blocks

NgRx State Management

For shared state across a large app, NgRx keeps one centralized, read-only store with a strict one-way flow. You never mutate state directly — you dispatch actions; reducers produce new state; effects handle async; selectors read.

Component ──dispatch(action)──► Reducer ──► Store (new state) ──select──► Component │ ▲ └──► Effect ──(API call)──► dispatch(success/failure)

Actions — "something happened" (the async triad)

export const search        = createAction('[Q] Search', props<{ payload: Req }>());
export const searchSuccess = createAction('[Q] Search Success', props<{ data: Q[] }>());
export const searchFailure = createAction('[Q] Search Failure', props<{ error: any }>());

Reducer — pure (state, action) => newState, never mutates

export const reducer = createReducer(initialState,
  on(search,        (s) => ({ ...s, isLoading: true })),
  on(searchSuccess, (s, { data }) => ({ ...s, isLoading: false, data })),
  on(searchFailure, (s, { error }) => ({ ...s, isLoading: false, error })),
);

Effect — side effects live here

getQuestions$ = createEffect(() => this.actions$.pipe(
  ofType(search),
  switchMap(({ payload }) => this.api.search(payload).pipe(
    map(res => searchSuccess({ data: res.items })),
    catchError(err => of(searchFailure({ error: err }))),  // map error to a failure action
  )),
));

Selector — memoized reads

export const selectState = createFeatureSelector<QState>('questions');
export const selectList  = createSelector(selectState, s => s.data);
Interview

"Why can't a reducer call an API?" Reducers must be pure — same inputs, same output, no side effects — so state changes are predictable, testable, and time-travel-debuggable. Async/side effects go in effects. Also know: immutability (why ...spread) is what lets OnPush and memoized selectors detect change by reference.

Module 10Advanced

Change Detection, Lifecycle, GraphQL, Testing

Change Detection & OnPush

Change detection keeps the screen synced to data. OnPush tells Angular to re-check a component only when: an input reference changes, an event fires in it, an async pipe emits, or a signal it reads changes — letting it skip whole subtrees.

Why the conventions exist

OnPush reacts to reference changes, not mutations. That's exactly why NgRx uses immutable updates, why signals use .set(), and why the async pipe is preferred — they all produce the notifications OnPush needs.

Lifecycle hooks

HookWhenUse for
constructorcreatedinject deps, set up effect()
ngOnInitafter first inputsinit, build forms, load data
ngOnChangeson input changereact to inputs (legacy; use signals/effect)
ngAfterViewInitafter view rendersDOM access, viewChild()
ngOnDestroybefore removalmanual cleanup

Modern shift: effect() replaces much of ngOnChanges; takeUntilDestroyed() replaces manual ngOnDestroy unsubscribes; afterNextRender/afterRender handle browser-only post-render work.

GraphQL & Apollo

Alongside REST, Angular apps use Apollo for GraphQL. A code-generation workflow (npm run generate) turns .graphql files into typed service classes. Queries use .watch().valueChanges (an Observable); mutations use .mutate(). Access is wrapped in a facade so components never touch Apollo directly.

Testing (Vitest / Jasmine)

describe('CountItemComponent', () => {
  let fixture: ComponentFixture<CountItemComponent>;
  beforeEach(async () => {
    await TestBed.configureTestingModule({ imports: [CountItemComponent] }).compileComponents();
    fixture = TestBed.createComponent(CountItemComponent);
    fixture.detectChanges();
  });
  it('should create', () => expect(fixture.componentInstance).toBeTruthy());
});

TestBed builds an isolated component; fixture wraps it (.componentInstance, .nativeElement, .detectChanges()); expect asserts. DI lets you provide mocks. Test types: unit, component (with DOM), integration, and E2E (Cypress/Playwright).

Content projection lets a component render caller-supplied markup — Angular's equivalent of React children / Web Component <slot>.

<div class="card"><ng-content></ng-content></div>

// multi-slot with select
<ng-content select="[slot=header]"></ng-content>

NgModules vs Standalone

Before Angular 14, components couldn't import anything themselves — they were grouped into NgModules. Since v17, standalone is the default.

@NgModule fieldContains
declarationscomponents/directives/pipes this module owns (each in exactly one module)
importsother modules (or standalone items) whose exports it needs
providersservices / DI tokens
exportswhat importers of this module may use

forRoot() vs forChild()

forRoot() — call once at the root; registers a library's global singletons + config (router, store core). forChild()/forFeature() — per feature; registers feature-scoped pieces without recreating singletons.

Providers & multi: true

{ provide: HTTP_INTERCEPTORS, useClass: AuthInterceptor, multi: true }

multi: true means "add to a collection under this token" — that's how the interceptor chain is built.

Standalone bootstrap modern

bootstrapApplication(AppComponent, {
  providers: [
    provideRouter(routes),                              // replaces RouterModule.forRoot
    provideHttpClient(withInterceptors([authInterceptor])), // functional interceptors
    provideAnimations(),
  ],
});

SSR, SSG & Hydration

ModeHTML builtTrade-off
CSRin browser, after JS loadssimple; poor SEO & first paint
SSRon server, per requestSEO + fast FCP; needs a Node server
SSGat build timefastest/cheapest; static content only

Add SSR with ng add @angular/ssr (creates server.ts, main.server.ts, provideServerRendering()).

Hydration

Hydration = the client app "adopting" server-rendered DOM instead of rebuilding it. Non-destructive hydration reuses existing nodes (no flicker); the old destructive behaviour threw the DOM away and re-rendered.

provideClientHydration(
  withEventReplay(),          // replay clicks made before hydration finished
  withIncrementalHydration(), // hydrate blocks lazily (v19+)
)

Incremental hydration pairs with @defer (hydrate on ...) — server-renders a block for SEO/paint but defers its JS until a trigger. The HTTP transfer cache serializes server GET responses into the HTML so the client skips duplicate fetches.

@defer (deferrable views)

@defer (on viewport) { <app-chart /> }
@placeholder { <skeleton /> } @loading { <spinner /> } @error { <p>Failed</p> }

Triggers: on idle (default), on viewport, on interaction, on hover, on timer(5s), when cond, prefetch on .... The block is auto code-split.

Server-safe code (top SSR bug)

window/document/localStorage don't exist on the server. Guard with isPlatformBrowser(inject(PLATFORM_ID)), or use afterNextRender() / afterRender() which run only in the browser after render. Hydration mismatches come from direct DOM manipulation, invalid HTML nesting, or rendering different content on server vs client.

Module 14Advanced

Internationalization (i18n)

Angular has a built-in, compile-time i18n system. You mark text, extract it, translate, and build one bundle per locale.

<h1 i18n="site header|Main page title@@homeTitle">Welcome</h1>
<img [alt]="alt" i18n-alt />   // translate an attribute with i18n-{attr}
  • i18n attribute marks translatable text. Syntax: meaning|description@@customId.
  • $localize — a tagged template for translating strings in TS: $localize`Hello ${name}`.
  • ICU expressions handle plurals/gender: {count, plural, =0 {no items} =1 {one item} other {{{count}} items}} and {gender, select, male {...} female {...} other {...}}.
  • Extract: ng extract-i18n → an XLIFF/XMB file translators fill in. Configure locales in angular.json; build produces one app per locale.
  • LOCALE_ID drives locale-aware date/number/currency pipes; register locale data with registerLocaleData().
Compile-time vs runtime

Angular's native i18n is compile-time (a separate bundle per language, best performance, ideal for SSR/SEO). Libraries like ngx-translate / Transloco do runtime i18n (switch language without rebuild, one bundle) — more flexible, slightly heavier. Many real apps use ngx-translate for dynamic language switching.

Module 15Advanced

Security & Accessibility

Security

  • XSS is the main threat. Angular auto-sanitizes values by context (HTML, style, URL, resource-URL) — interpolation is always escaped, so {{ userInput }} is safe by default.
  • [innerHTML] binds sanitized HTML (strips scripts). To render trusted raw HTML, use DomSanitizer.bypassSecurityTrustHtml(...) — but only on content you fully trust (this is the risky escape hatch behind pipes like nlToBr/safe).
  • Avoid ElementRef.nativeElement.innerHTML = ... and template concatenation of user data. Use Angular's bindings.
  • CSP (Content Security Policy) + Trusted Types add defense-in-depth. Angular integrates with Trusted Types. Also: HttpOnly cookies / CSRF tokens (Angular's HttpClient has XSRF support), and never put secrets in the client bundle.
Interview trap

"How does Angular prevent XSS?" Contextual auto-sanitization + always-escaped interpolation. You only become vulnerable when you deliberately bypass it (bypassSecurityTrust*) or manipulate the DOM directly.

Accessibility (a11y)

  • Target WCAG AA: sufficient color contrast, visible focus states, full keyboard operability.
  • Use semantic HTML first (<button>, <nav>, <label>); add ARIA only to fill gaps (aria-label, role, aria-live for dynamic announcements).
  • Focus management: move focus into dialogs, trap it, restore on close. The Angular CDK a11y module provides FocusTrap, LiveAnnouncer, and FocusMonitor.
  • Tools: axe for automated checks; test with a keyboard and a screen reader.
Module 16Advanced

Performance, Modern Reactivity & Tooling

Performance levers

  • OnPush change detection everywhere.
  • track in @for to reuse DOM nodes.
  • Lazy loading routes (loadChildren) and @defer for widgets.
  • Preloading strategies: PreloadAllModules or a custom strategy to warm lazy chunks after load.
  • Pure pipes / computed() instead of template method calls.
  • trackBy, virtual scrolling (cdk-virtual-scroll), NgOptimizedImage for images, bundle budgets.

Zoneless change detection modern

Historically Angular used Zone.js to monkey-patch async APIs and trigger change detection automatically. Zoneless (stable in recent versions) drops Zone.js and drives CD from signals, the async pipe, and event bindings instead — smaller bundle, better performance, clearer mental model. Enabled via provideZonelessChangeDetection().

Interview

"What is Zone.js and what replaces it?" Zone.js patches setTimeout/promises/events so Angular knows when to run change detection. Signals make change tracking explicit and fine-grained, enabling zoneless apps where CD runs only when a signal/async pipe/event actually changes something.

Tooling

Angular CLI (ng generate, ng serve, ng build), ng update (automated migrations for version upgrades), Angular DevTools (component tree, DI tree, profiler), Language Service (IDE completion/diagnostics), and schematics for scaffolding.

AppendixInterview Prep

Popular Interview Questions & Answers

Grouped by topic and ordered roughly junior → senior. Read the question, answer it aloud, then expand to check. Anything marked modern is the current best practice; interviewers love when you can contrast it with the legacy approach.

Core concepts
What is Angular, and how does it differ from a library like React?

Angular is a full, opinionated framework (routing, forms, HTTP, DI, testing all included), built with TypeScript. React is a UI library that leaves those choices to you. Angular uses a component + template + DI architecture and (increasingly) signals for reactivity.

What is a component, and what are its main parts?

A reusable unit of UI: a class with a @Component decorator (metadata: selector, template, styles, change detection), a template (HTML with bindings), and scoped styles. Components form a tree.

Explain the difference between [ ], ( ), and [( )].

[prop] = property/input binding (data in). (event) = event/output binding (event out). [(x)] = two-way binding, sugar for [x]="v" (xChange)="v=$event".

What are standalone components and why do they matter? modern

Components/directives/pipes that declare their own dependencies via imports, with no owning NgModule. Default since v17. Benefits: less boilerplate, better tree-shaking, simpler lazy loading (lazy-load a component or a routes array directly), easier testing.

Interpolation vs property binding — is {{x}} the same as [textContent]="x"?

Nearly. Interpolation coerces to string and concatenates; property binding sets the actual DOM property and can carry any type. Use interpolation for text, property binding for non-string properties and expressions.

Signals & reactivity
What is a signal? How do you read and write one?

A reactive container for a value. Read by calling it: count(). Write with .set(v) or .update(fn). When it changes, Angular re-renders consumers (even zoneless). Never use .mutate().

computed() vs a method vs effect()?

computed() = a memoized derived value; recomputes only when its signal dependencies change. A method runs on every change-detection cycle (avoid in templates). effect() runs a side effect when signals change — use sparingly, not for deriving values.

How do signals relate to RxJS? How do you bridge them?

Signals are synchronous, pull-based, glitch-free state; RxJS models async streams over time. Bridge with toSignal(obs$) and toObservable(sig). Use signals for component state, RxJS for events/async pipelines.

What is input() / output() / model()? modern

Signal-based component I/O. input() (and input.required()) replaces @Input — read as a signal. output() replaces @Output. model() creates a two-way (input + xChange output) writable signal for [(x)] binding.

Directives, templates, pipes
@if/@for/@switch vs *ngIf/*ngFor/*ngSwitch?

The @-blocks are the modern built-in control flow (v17+): faster, better type-narrowing, built into the compiler, with @empty/@else. The *ng* structural directives are legacy but still supported. @for requires track.

Why is track required in @for?

It identifies each item so Angular can reuse/move DOM nodes instead of destroying and recreating the whole list on every change — huge for performance and preserving element state/focus. Use a stable unique id.

Difference between a component, an attribute directive, and a structural directive?

Component = directive with a template. Attribute directive = changes appearance/behaviour of an existing element ([clickOutside]). Structural directive = changes DOM layout by adding/removing elements (*ngIf; the @-blocks now cover this).

Pure vs impure pipe?

A pure pipe (default) recomputes only when its input reference changes — cached, fast. An impure pipe runs every CD cycle (e.g. async). Prefer pure pipes; avoid method calls in templates for the same reason.

ng-content vs ng-template vs ng-container?

ng-content projects caller content into a slot (with select for multi-slot). ng-template defines markup not rendered until asked (a TemplateRef, rendered via ngTemplateOutlet). ng-container is a grouping element that renders no DOM.

Dependency Injection & services
How does Angular's DI work? What is a provider?

A hierarchical injector system resolves dependencies by token. A provider tells the injector how to create a token's value: { provide: TOKEN, useClass/useValue/useFactory/useExisting }. Injectors form a tree (root → route → component); resolution walks up until found.

providedIn: 'root' vs providing in a component?

'root' = a single app-wide singleton (tree-shakable). Providing at a component creates a new instance per component instance and its children — useful for scoped state. Providing in a lazy route scopes to that route.

What does multi: true do?

Registers multiple values under one token as an array instead of overwriting. It's how the HTTP interceptor chain, validators, and app initializers are assembled.

What is an InjectionToken and when do you use one?

A typed token for injecting non-class values (config objects, primitives, functions) or for abstracting a dependency so a generic service doesn't depend on a concrete app class. Combine with @Optional() so code still works when no provider is registered.

RxJS & HTTP
Observable vs Promise?

Promise: single value, eager, not cancellable. Observable: 0..n values over time, lazy (runs on subscribe), cancellable, composable via operators. Angular HTTP returns Observables.

switchMap vs mergeMap vs concatMap vs exhaustMap?

switchMap: cancel previous inner, keep latest (search). mergeMap: run all concurrently (parallel independent calls). concatMap: queue in order (sequential saves). exhaustMap: ignore new while one is running (prevent double-submit, polling).

How do you avoid memory leaks from subscriptions?

Prefer the async pipe (auto-unsubscribes). For manual subscriptions use takeUntilDestroyed(destroyRef) modern, or takeUntil(destroy$) in ngOnDestroy, or the untilDestroyed lib. Operators that complete (like HTTP + first()) also self-clean.

What is an HTTP interceptor and give real uses.

Middleware that transforms every request/response. Uses: attach auth tokens, add tenant/locale headers, global error handling, retry, logging, caching. Modern form is a functional HttpInterceptorFn registered via provideHttpClient(withInterceptors([...])); legacy is a class + HTTP_INTERCEPTORS multi-provider.

How would you build a debounced typeahead?

control.valueChanges.pipe(debounceTime(300), distinctUntilChanged(), switchMap(t => api.search(t))). debounceTime waits for a pause, distinctUntilChanged skips duplicates, switchMap cancels stale requests.

Forms
Reactive vs template-driven forms?

Reactive: model in TS (FormGroup/FormControl), synchronous, testable, scales, good for dynamic/complex forms. Template-driven: model inferred from ngModel directives in HTML, async, simpler for tiny forms. Prefer reactive.

How do you write a custom validator? A cross-field validator?

A function (control) => ValidationErrors | null returning e.g. { invalidX: true } or null. Cross-field validators are placed on the FormGroup and read multiple child controls. Async validators return an Observable/Promise of errors.

What is ControlValueAccessor?

An interface that lets a custom component act as a native form control — implement writeValue, registerOnChange, registerOnTouched, setDisabledState and provide NG_VALUE_ACCESSOR. Then a parent can use [(ngModel)] or formControlName on your component.

Routing
How does lazy loading work and why use it?

loadChildren: () => import('./x').then(m => m.routes) downloads a feature's code only when its route is first visited, shrinking the initial bundle and speeding startup. Standalone lets you lazy-load a single component too.

Types of route guards?

canActivate (enter), canActivateChild (enter children), canMatch/canLoad (match/download a lazy route), canDeactivate (leave — unsaved-changes prompts). Modern guards are functions returning boolean | UrlTree | Observable<...>.

How do you read route params, and snapshot vs observable?

route.snapshot.paramMap.get('id') for a one-time read; route.paramMap.subscribe(...) when the param can change while staying on the same component (Angular reuses it). Same distinction for query params and data.

What is a resolver and a trade-off of using one?

Pre-fetches data before the route activates so the view opens ready. Trade-off: it delays navigation until data arrives (no loading state in-component), so overuse hurts perceived speed; often letting the component fetch with a spinner is better.

State management (NgRx)
When do you actually need NgRx?

When lots of components share and mutate the same state, you need predictable/traceable updates, undo/time-travel, or complex async coordination. For local or simple state, signals/services are enough — don't add NgRx by default.

Explain the NgRx data flow.

Component dispatches an action → reducer (pure) produces new state → store updates → selectors (memoized) emit to components. Side effects (API) run in effects, which listen for actions and dispatch success/failure actions.

Why must reducers be pure and immutable?

Purity makes state changes deterministic, testable, and enables time-travel debugging. Immutability (new references) is what lets OnPush and memoized selectors detect change cheaply by reference comparison.

Why put API calls in effects, not services or components?

Effects centralize side effects and their outcomes (dispatch success/failure, navigate, catch errors) while keeping reducers pure and services thin (services just return Observables). This separation keeps the whole loop predictable.

What does a selector's memoization give you?

It caches the last result and only recomputes when inputs change, avoiding redundant work and unnecessary emissions/re-renders. Selectors also compose, so you derive complex views without recomputing everything.

Change detection & performance
What triggers change detection, and what does OnPush change?

By default (Zone.js) any async event (clicks, timers, HTTP) triggers a full CD pass. OnPush limits a component to re-check only on input reference change, an event within it, an async emission, or a signal read change — letting Angular skip subtrees.

What is Zone.js and what is zoneless CD? modern

Zone.js monkey-patches async APIs so Angular knows when to run CD automatically. Zoneless removes it and drives CD explicitly from signals, the async pipe, and event bindings — smaller bundle, better perf, no over-triggering. Enabled with provideZonelessChangeDetection().

Name five ways to improve Angular performance.

OnPush; track in @for; lazy loading + @defer; pure pipes/computed() over template methods; virtual scrolling; NgOptimizedImage; preloading strategies; avoiding unnecessary subscriptions; bundle budgets and tree-shaking.

What is @defer and its triggers?

A template block that lazy-loads its content and dependencies (auto code-split) with @placeholder/@loading/@error. Triggers: on idle, on viewport, on interaction, on hover, on timer, when cond, and prefetch on ....

Lifecycle & DOM
List the lifecycle hooks in order.

ngOnChanges → ngOnInit → ngDoCheck → ngAfterContentInit → ngAfterContentChecked → ngAfterViewInit → ngAfterViewChecked → ngOnDestroy. Modern: signals/effect and afterNextRender/afterRender reduce the need for several.

Why can't you access a viewChild element in ngOnInit?

The view isn't rendered yet in ngOnInit. View queries resolve by ngAfterViewInit (or read the viewChild() signal after that). DOM measurement/focus belongs there or in afterNextRender.

viewChild vs contentChild?

viewChild queries elements/components in the component's own template. contentChild queries content projected into it via ng-content.

SSR, hydration, i18n
CSR vs SSR vs SSG — when to use each?

CSR for internal apps where SEO/first-paint don't matter. SSR for public, dynamic, SEO-sensitive pages (renders real HTML per request). SSG for content known at build time (docs, marketing) — prerendered static files, fastest and cheapest.

What is hydration, and destructive vs non-destructive?

Hydration is the client app taking over server-rendered DOM. Non-destructive (modern, via provideClientHydration()) reuses the existing DOM — no flicker. Destructive (old) threw it away and re-rendered.

What is incremental hydration and event replay?

Incremental hydration (withIncrementalHydration() + @defer (hydrate on ...)) hydrates blocks lazily on a trigger, deferring their JS. Event replay (withEventReplay()) captures user events during the pre-hydration window and replays them once hydrated.

Top SSR bug: what breaks and how do you fix it?

Using browser globals (window, document, localStorage) on the server crashes it. Guard with isPlatformBrowser(inject(PLATFORM_ID)) or use afterNextRender()/afterRender() (browser-only). Also avoid direct DOM manipulation and invalid HTML that cause hydration mismatches.

Angular built-in i18n vs ngx-translate?

Built-in is compile-time: i18n attribute + $localize, extract with ng extract-i18n, one bundle per locale — best performance/SEO but a rebuild to switch. ngx-translate/Transloco are runtime: JSON dictionaries, switch language live, one bundle — more flexible, slightly heavier.

Security & accessibility
How does Angular protect against XSS?

Contextual auto-sanitization (HTML/style/URL/resource-URL) and always-escaped interpolation. Binding to [innerHTML] is sanitized. You only open a hole by bypassing sanitization (bypassSecurityTrust*) or manipulating the DOM/strings directly.

When is DomSanitizer.bypassSecurityTrustHtml appropriate?

Only for content you fully control/trust (never raw user input). It disables sanitization for that value, so misuse reintroduces XSS. Prefer letting Angular sanitize.

How do you make an Angular app accessible?

Semantic HTML first, ARIA to fill gaps; WCAG AA contrast; visible focus; full keyboard support; focus management for dialogs/menus (CDK FocusTrap, LiveAnnouncer); announce dynamic changes with aria-live; test with axe, keyboard, and a screen reader.

Architecture & senior-level
NgModule vs standalone — how would you migrate?

Standalone removes NgModules; components import their own deps and the app bootstraps via bootstrapApplication + provideX(). Migrate incrementally (they interop): convert leaf components first with the CLI schematic, replace SomeModule.forRoot() with providers, then drop modules. A hybrid app is normal mid-migration.

How do you decide between signals, RxJS, and NgRx for state?

Signals for local/component and simple shared state (via a service). RxJS for async streams and event orchestration. NgRx for large, cross-cutting, shared state needing traceability and structure. Use the lightest tool that fits; combine them (e.g. signals + toObservable).

What makes a service well-designed?

Single responsibility; returns Observables rather than subscribing; doesn't inject UI concerns (MatDialog/Router/Store) unless that's its job; depends on abstractions (InjectionToken) not concrete app classes; reference-counted loading state; no dead/legacy public API.

How does the CLI help with upgrades and consistency?

ng update runs automated migration schematics for breaking changes across versions; ng generate scaffolds consistent artifacts; lint + budgets enforce standards; DevTools and the Language Service catch issues early. Staying current keeps the app fast and secure.

Explain the OnPush + immutability + signals connection.

They're one system. OnPush detects change by reference or signal notification. Immutable updates (NgRx ...spread) and signal writes both produce those signals, so the UI updates correctly and cheaply. Mutating in place under OnPush is the classic "why isn't my view updating?" bug.
